# 填表觀察記錄 — 邊填 register 邊記，這就是 Move 1 的規格

手填 `register.csv` 時，每撞到一個「要想一下」「不好填」「有例外」的地方，就記在這裡。
你不是在抱怨，你是在替自動掃描器**標出它未來會踩的雷**。每一條觀察，右邊都對應一個 Move 1 要做的決策。

填法：在每題下面記「我這個專案的實際情況」，沒撞到就寫「無」。

---

## A. 圖號 `drawing_no`

- [ ] **A1** 圖號從哪裡讀到最準？檔名？標題欄？兩者一致嗎？
  → 決定 Move 1 掃描器優先信任哪個來源。
- [ ] **A2** 有沒有圖號格式不符 `字母-數字`（如 `A-201`）的？例如純數字、中文前綴、`A201` 無破折號、`A-201a` 有尾碼。
  → 決定 regex 要放寬到什麼程度（現在 `server.py` 那條只認 `A-201`）。
- [ ] **A3** 有沒有兩張圖圖號相同（不同專案 / 不同版本混在一起）？
  → 決定唯一鍵要不要加上 `project_id`。

_記錄：_
1.好像通常是作業檔的檔名才會有明確的圖號，或者是在工作中單獨修改產出的PDF。如果是為了彙整正式文件的話有時候會多張圖在一個檔案裏面，看公司怎麼樣分類。
  不過當然會有產生疑慮的還是作業中的檔案啦
2.要抓的話也可以去索引表找最快

## B. 標題欄 / 圖名 `title`

- [ ] **B1** PDF 是「向量圖（可選取文字）」還是「掃描影像（要 OCR）」？大概各占多少？
  → 決定 Move 1 讀標題欄能不能純文字萃取，還是要上 OCR。**這題影響最大。**
- [ ] **B2** 標題欄位置固定嗎（都在右下角）？格式跨圖一致嗎？
  → 決定能不能用固定區域裁切，還是每張都要全頁找。
- [ ] **B3** 圖名裡有沒有夾帶棟別/樓層資訊（如「管理大樓 2F 平面圖」）？還是圖名很精簡（只有「平面圖」）？
  → 決定 building/floor 能不能從圖名切出來。

_記錄：_
1.更精確的資料來源應該是每一張圖內的圖標，這個部分可能可以很明確的自動化，且日後不太會改。 
2.且發現好像有導入BIM的話可以更快的抓到，只要BIM檔案裏面有圖紙清單(圖紙明細表)，就可以無痛匯出。
3.或者是最直接的，所有專案應該都有索引表，直接去那邊抓就可以了。

## C. 棟別 / 樓層 `building` `floor`

- [ ] **C1** 棟別在真實資料裡怎麼標？跟 `glossary.json` 的代號對得起來嗎？
  → 補進詞彙表的 `buildings`。
- [ ] **C2** 有多少圖「沒有樓層」（大樣、系統圖、配置圖、剖面）？
  → 決定 floor 空白是常態，萃取別把空白當錯誤。
- [ ] **C3** 有沒有一張圖跨多樓層 / 多棟別？
  → 決定對應要不要支援「一圖多鍵」。

_記錄：_
1.棟別不一定每一個專案都有，多數專案只有一棟，所以可能在圖面裡面沒有特別標哪一棟，就不會有棟別問題
2.應該可以說有一半以上的圖都是沒有樓層的，但是可以從所有圖面列表裡面清楚看到有哪些平面圖，通常會窮舉所有樓層。
  而剩下的多為立面、剖面、局部平面、細部詳圖還有多項說明文字。也常常看到多樓層的平面可能會出現在同一張圖，可能是用於交代次要資訊，而非主要空間平面。

  → 補進 `glossary.json` 的 `disciplines`。

## E. 版次 `current_ver`

- [ ] **E1** 版次在哪？檔名（`_v3.0-r08`）？標題欄（`Rev. C`）？兩者一致嗎？
  → 決定版次的權威來源。
- [ ] **E2** 版次怎麼編？跟 `v大.小-r流水` 一樣嗎？還是 `A/B/C`、`第3版`、日期版？
  → 決定 `bump_version`（`server.py:215`）要不要改，才對得上你們真實編碼。

_記錄：_

## F. 檔案配對 `cad_path` `pdf_path`

- [ ] **F1** 同一圖號，CAD 和 PDF 能靠圖號自動配對嗎？命名一致嗎？
  → 決定配對邏輯。
- [ ] **F2** 一個圖號有沒有多個 PDF（多版本並存）？怎麼分辨哪個是現行版？
  → 決定「取最新版」的判準（現在是靠 mtime，可能不可靠）。
- [ ] **F3** 有沒有孤兒檔（有 PDF 沒 CAD、或反之）？資料夾裡有沒有非圖檔（會議記錄、Excel、備份 `~$`）混進來？
  → 決定掃描器的過濾與容錯。

_記錄：_

## G. 別名 `aliases` ★最重要

- [ ] **G1** 隨手翻 3~5 封你真實的信/筆記，裡面提到圖的講法，有幾種**沒被你 register 的 aliases 蓋到**？
  → 這就是冷啟動缺口的真實大小。
- [ ] **G2** 有沒有「同一個別名可能指到多張圖」的情況（如「平面圖」太籠統）？
  → 決定萃取遇到歧義時，要走「請人工挑」而不是硬猜（低信心邊界）。
- [ ] **G3** 別名裡有沒有錯字、簡稱、英數混寫（`B1F`/`B1`/`地下一樓`）？
  → 決定要不要做模糊比對 / 正規化。

## H. 整體覆蓋率

- [ ] **H1** 這個專案「進行中的圖」大概幾張？你填了幾張？覆蓋率抓到 90% 了嗎？
- [ ] **H2** 有沒有哪種圖「這個模型根本裝不下」（3D、地形圖、非圖面文件）？
  → 決定邊界：哪些明確不進 register。
