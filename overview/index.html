WHAT HAPPENS INSIDE THE TOOL

五個步驟，讓一則交辦
走到可靠的正式版本。

01 / 接收

把零散交辦接進來

工具掃描信件與筆記資料夾，把每一則尚未處理的內容放進收件匣。此時保留來源文字，避免需求一開始就遺失上下文。

02 / 執行

Request 成為設計待辦

確認後的 Request 會掛上圖號、修改點、期限與 Designer。設計人員不必在訊息裡找線索，而是在工作台從圖面直接開始處理。

Request 草稿REQ-043
來源 · 0718 工務會議調整二樓天花配置

會議室高度 2.7m，更新空調出風口。

已連結圖面A-201 · 二樓平面圖開啟圖面頁面 ↗
03 / 檢查

在圖面上核對改動

pending PDF 與 Request 位置一起呈現。Requester 能在圖面上比對成果；有問題就新增重修註記，而不是用模糊的文字往返。

A-201 · pending拖移註記定位

雲型註記移動中
04 / 確認

決定這次修改是否通過

Requester 在 Request 詳情中確認結果。通過就繼續進版；不符則填寫原因、標出問題位置，交回 Designer 進行下一輪修改。

Request 詳情待確認

05 / 進版

留下可追溯的正式紀錄

確認後，正式 PDF 與版本歷程同步更新。下一次有人問「為什麼這樣改」，團隊可以從圖面一路回到需求與決策。
