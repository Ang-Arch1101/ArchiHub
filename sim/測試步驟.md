# 單機多人作業模擬 — 完整測試步驟

依此逐步驗證多人流程。每步都有**操作**與**預期結果**；需要客觀確認的地方附**API 驗證指令**（另開一個終端機貼上即可）。

> 前提：Python 3.10+。所有資料來自合成信件，不碰真實文件。
> 看板是**確定性**的（同批信件、同順序），下面引用的 REQ 編號與人名穩定；若你重新產生過信件，請以 `run_sim.py` 印出的看板為準。

---

## 0. 啟動與冒煙測試

**操作**
```bash
python sim/run_sim.py --reset
```
（`--reset` 清掉舊 SIM 資料重佈。8734 沒開會自動幫你啟動 server。）

**預期結果（終端機印出看板）**
- 14 筆任務，分布：🔴待接受 6、🔴鎖定編輯中 2、🟡待確認 2、🔴退回重修 1、🔴任務被拒 1、🟢已進版 2
- 圖號 11 個、收件匣留 26 封

**API 驗證（可選）**
```bash
curl -s localhost:8734/api/state | python3 -c "import json,sys;s=json.load(sys.stdin);from collections import Counter;print('狀態:',dict(Counter(r['status'] for r in s['requests'])),'| 收件匣:',len(s['inbox']),'| 專案:',s['project']['id'])"
# 預期：狀態: {'red': 10, 'yellow': 2, 'green': 2} | 收件匣: 26 | 專案: sim
```

**UI 冒煙**
開 <http://localhost:8734>：
- [ ] 右上專案是「SIM · 多人作業模擬」
- [ ] 頂部「📥 收件匣」badge 顯示 26
- [ ] 「🗂 工作台」左欄「📋 全部」有 14 筆，紅/黃/綠三色燈都看得到
- [ ] 點任一筆，中間出現該圖號的 PDF（自動生成的示意平面）

## 測試 A：設計端完整循環 🔴→🟡→🟢（跨兩個身分）

**A-1　以 designer 接受並提交**
1. 設定「我的名字」＝ **阿勳**。
2. 進「🔧 待辦作業」→ 應看到 5 筆（REQ-001、003、005、009、013）。
3. 點 **REQ-001**（E-301）。
4. 按「▶ 接受任務・前往修改」→ 出現「本地副本編輯中」（此機無 CAD 會提示未能開啟，正常）。
5. 按「⬆ 完成並提交」。

**預期**：REQ-001 轉 🟡；出現 pending PDF；訊息「已提交 → 待 黃國強課長 確認」。

**A-2　以 requester 確認進版**
6. 設定「我的名字」＝ **黃國強課長**。
7. 進「👁 待我確認」→ 應看到 REQ-001。
8. 按「🧾 檢視提交的 PDF」看圖，再按「✓ 確認符合要求 → 正式進版」。

**預期**：REQ-001 轉 🟢；版本歷史新增一筆；出圖資料夾產生新流水號 PDF、pending 消失。

**API 驗證**
```bash
curl -s localhost:8734/api/state | python3 -c "import json,sys;s=json.load(sys.stdin);r=[x for x in s['requests'] if x['id']=='REQ-001'][0];print('REQ-001 狀態:',r['status'])"
# A-1 後預期 yellow；A-2 後預期 green
```

## 測試 B：需求端退回重修 🟡→🔴（帶問題標註）

1. 設定「我的名字」＝ **陳志明監造**。
2. 進「👁 待我確認」→ 應看到 **REQ-007**（E-301）。
3. 按「↩ 退回重修」→ 進入退回模式（提示列變色）。
4. **在中間圖面上點一下**要修改的位置 → 出現紫色 ↩ 標記。
5. 右欄填退回原因（例：「位置不對，應靠牆」）→ 按「送出退回」。

**預期**：REQ-007 轉 🔴；訊息「已退回 阿勳 重修（第 1 輪）」。

6. 設定「我的名字」＝ **阿勳** → 進「🔧 待辦作業」點 REQ-007 → 詳情頁應出現**紫色退回說明**（第 1 輪、原因、時間），圖上有紫色 ↩ 問題點。
7.（可續走）按「⬆ 完成並提交」→ 再轉 🟡，回到 requester 手上。

**API 驗證**
```bash
curl -s localhost:8734/api/state | python3 -c "import json,sys;s=json.load(sys.stdin);r=[x for x in s['requests'] if x['id']=='REQ-007'][0];print('狀態:',r['status'],'| rework:',r.get('rework',{}).get('round'),r.get('rework',{}).get('reason'))"
```

---

## 測試 C：設計端拒絕任務 + 回信 🔴

1. 設定「我的名字」＝ **阿勳**。
2. 進「🔧 待辦作業」點一筆待接受紅燈（例 **REQ-003**，P-301）。
3. 按「⛔ 拒絕・退回詢問 Requester」→ 填疑問（例：「哪一區的茶水間？」）。
4. 按「送出並開啟回信」。

**預期**：跳出系統預設信件程式的回信視窗（`mailto:`，主旨 `Re: …（REQ-003）`、內文帶原始需求引文）；REQ-003 出現「已退回 李文成工程師 要求釐清」。

5. 觀察開場已有的 **REQ-009**（任務被拒・待釐清）：點它可看到拒絕說明與「再次回信」按鈕；按「▶ 已釐清・接受任務」即解除拒絕、回到正常紅燈。

> 註：現場筆記/口頭來源（無 email）按拒絕時，會顯示降級提示而非開回信——可挑一筆 📝 來源任務對照。

---

## 測試 D：從收件匣自動萃取新任務（信件 → 任務）

1. 頂部切到「📥 收件匣」→ 應有 26 封（📧 信件 / 📝 筆記）。
2. 任選一封按「✨ AI 萃取 → 產生 Request」（規則式解析，欄位可改）。
3. 選對應圖面、指派 designer（例 小柯）、確認建立。

**預期**：收件匣該封標記為「已轉為 REQ-xxx」；新任務出現在該 designer 的「🔧 待辦作業」。切成該 designer 即可接續測試 A。

**API 驗證**
```bash
curl -s localhost:8734/api/state | python3 -c "import json,sys;s=json.load(sys.stdin);print('目前任務數:',len(s['requests']))"
# 每萃取一筆，任務數 +1
```

## 測試 F：回歸 / 邊界

- **非法轉移擋下**：對一筆紅燈任務打 confirm 應被拒。
  ```bash
  curl -s -X POST localhost:8734/api/requests/REQ-001/confirm -H 'Content-Type: application/json' -d '{"actor":"x"}'
  # 若 REQ-001 尚為 red，預期 {"ok": false, "error": "狀態 red 不允許動作 confirm"}
  ```
- **不影響原專案**：右上專案下拉切回「928816」，你原本的資料完好；再切回「SIM」繼續。
- **訓練資料落地**：退回/拒絕/標註都寫入 `data/sim/corrections.jsonl`。
  ```bash
  wc -l data/sim/corrections.jsonl && tail -1 data/sim/corrections.jsonl
  ```
